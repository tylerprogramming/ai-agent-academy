# ai-agent-academy

A landing page for an AI agent course site (React, Vite, Tailwind), with a floating chat widget. The widget is OpenAI ChatKit, backed by an Agent Builder workflow.

> **Agent Builder shuts down on 2026-11-30.** OpenAI is deprecating Agent Builder. The hosted workflow that `CHATKIT_WORKFLOW_ID` points to stops working on that date, and so does this chat widget ([ChatKit guide](https://developers.openai.com/api/docs/guides/chatkit)). ChatKit itself stays available. To keep the chat:
>
> 1. Export the workflow as Agents SDK code: open it in Agent Builder, then **Code** > **Agents SDK** ([Migrate from Agent Builder](https://developers.openai.com/api/docs/guides/agent-builder/migrate-from-agent-builder)).
> 2. Run it behind your own ChatKit server (`pip install openai-chatkit`), then point the widget at that server ([Advanced ChatKit integrations](https://developers.openai.com/api/docs/guides/custom-chatkit)).
>
> Export the workflow before 2026-11-30, while Agent Builder can still open it.

## How it fits together

- `src/components/FloatingChat.tsx` opens `src/components/ChatComponent.tsx`, which mounts `<ChatKit>` from `@openai/chatkit-react`. `index.html` loads the ChatKit web component from `cdn.platform.openai.com`.
- To start a session, `src/chatkit.ts` POSTs a per-browser `deviceId` to the Supabase edge function `chatkit-session`.
- `supabase/functions/chatkit-session/index.ts` calls `POST https://api.openai.com/v1/chatkit/sessions` with your OpenAI key and `CHATKIT_WORKFLOW_ID`, then returns the `client_secret` to the browser.

## Setup

1. `npm install`
2. Copy `.env.example` to `.env` and set `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`.
3. Deploy the edge function and set its secrets:

   ```bash
   supabase functions deploy chatkit-session
   supabase secrets set OPENAI_API_SECRET_KEY=sk-... CHATKIT_WORKFLOW_ID=wf_...
   ```

4. `npm run dev`

Other scripts: `npm run build`, `npm run lint`, `npm run typecheck`.

## Before you deploy it publicly

`chatkit-session` does not check who is calling. The only credential the browser sends is the Supabase anon key, which Vite puts in the public bundle, and `deviceId` is generated by the browser. So anyone who loads the site can mint ChatKit sessions billed to your OpenAI account. CORS is also `*`.

Before a public deploy:

- require a signed-in Supabase user in the function (`supabase.auth.getUser()` on the request's JWT);
- restrict CORS to your site's origin;
- add a per-user limit.

The ChatKit guide's session example uses the same pattern: it authenticates the user first, then passes their stable ID as `user`.
